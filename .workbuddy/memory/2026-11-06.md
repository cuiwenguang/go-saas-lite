## 修复：登录后白屏（真 bug，vue-router 双重前缀）

- 根因：路由表路径已写全前缀（`/admin/login`），而 `createWebHistory("/admin/")` 又传了 base → 双重前缀。登录成功后 push 到失配路由，生产构建剥掉 vue-router 警告，`router-view` 匹配不到组件 → 白屏且无任何报错。排查时用 puppeteer-core 驱动本机 Edge 无头复现，日志暴露 URL 变成 `/admin/admin/login?redirect=/login`。
- 修复：两个 router 去掉 base 参数（`createWebHistory()`），路由表保持全前缀写法；顺手给两个 index.html 加了内联 SVG favicon（消掉 404）。
- 验证：无头浏览器端到端跑通 /admin 与 /app 双侧登录 → dashboard 完整渲染（菜单/统计卡/图表/表格），pageerror 与 4xx 均为零。
- 经验：① SPA 白屏无报错时优先怀疑路由失配（生产构建无警告）；② vue-router base 与路由表前缀只能二选一；③ 无头 Edge (`msedge.exe`) + puppeteer-core 是本机可用的 UI 调试路径，调试脚本用完即删。

## 修复：登录后立刻被踢回登录页（真 bug）

- 根因：`shared/http/client.ts` 从未注入 `Authorization` 头——登录成功后请求 `/me` 不带 token，mock 返回 401 → 触发 onUnauthorized → logout + 弹回登录页，表现为"登录不上"。
- 修复：client.ts 增加 `setTokenProvider()` + 请求拦截器注入 `Bearer <token>`（注入模式，避免 client 反向依赖 auth store 循环 import）；main.admin.ts / main.tenant.ts 接线 `setTokenProvider(() => useAuthStore().token)`；mock/routes.ts 的 bearer() 兼容 axios 1.x AxiosHeaders 实例（优先 `h.get("Authorization")`）。
- 经验：真实后端接入时这套 token 注入/401 处理就是挂 refresh 队列的位置，契约已在。

## 前端技术选型定案（多轮讨论收敛，最终由 CONVENTIONS-FRONTEND.md 固化）

- 整体形态：营销站（Go html/template + Tailwind，住 `internal/web/`）与控制台（Vue SPA，住 `web/`）分离；单 Go 进程按路由分发：`/` 模板页、`/app/*` 租户控制台、`/admin/*` 平台后台、`/api/*` 接口。
- 控制台：**单 Vue 项目双入口**（admin.html + tenant.html，Vite 多入口 + `base:"./"` + 路由运行时判断前缀），不用 monorepo/workspace。Element Plus（按需）+ axios + pinia（仅 auth/app/tenant 三 store）+ vxe-table + echarts。控制台**不引 Tailwind**（preflight 与 Element 冲突）。
- 营销站 Tailwind：开发期 CDN（@tailwindcss/browser@4），上线前 `npx @tailwindcss/cli --minify` 产单 CSS embed 进 Go；v4 需 `@source` 显式指向 Go 模板目录。
- Element「行政风」改造方案：theme.css 全局覆盖（圆角 8、边框弱化、表头透明、--brand + color-mix 派生色阶）+ 布局层（统计卡、页面 max-width、分栏登录页）。不换库。
- 放弃的方案及原因：shadcn-vue（投资期 3-5 天、复杂组件缺失，用户要快）；monorepo（单人同节奏双入口收益不足）；SPA 合一（base 路径冲突）。
- 不从 admin 脚手架（pure-admin/geeker）改造：双入口是结构性差异，契约层反正重写，规范债大。从零搭约 3 个工作日。
- 小程序路线预留：uni-app（Vue 3），只共享逻辑层（http/auth 适配器模式），UI 不共享；Vue 3 选型的关键理由。
- 前端规范：仓库根 `CONVENTIONS-FRONTEND.md` 已创建（10 节：硬边界/目录/组件/请求/权限/样式/状态/CI/升级触发条件/Go 接缝）。
- 后端 P0 前置接口（前端开发硬依赖）：POST /api/auth/refresh、GET /me（含 permissions: string[]）、POST /api/public/v1/signup + 子域名查重、GET /public/plans。
- 推进顺序：P0 后端接口 → P1 web 双入口骨架（theme.css + 布局壳 + 登录 + /me 链路）→ P2 营销站 → P3 租户控制台 → P4 平台后台 → P5 品牌化（--brand 注入）。
